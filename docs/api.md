# API reference

Base URLs:

- Through the UI/nginx proxy: `http://localhost:3000/api/v1`
- Direct API: `http://localhost:8080/api/v1`
- Liveness through the UI: `http://localhost:3000/healthz` (a static nginx response)
- Probes on the API: `http://localhost:8080/healthz`, `http://localhost:8080/readyz`,
  and `http://localhost:8080/api/v1/health`

Only `/healthz` and `/api/` are proxied by the frontend. `/readyz` is intentionally
not exposed through nginx; use the loopback API port for readiness checks.

There is no authentication in the application. Deploy behind an authenticating
reverse proxy if the instance is shared. The API does not add CORS headers; use
the same-origin nginx proxy, or add your own gateway.

## Conventions

- Request and response bodies are JSON unless noted.
- Uploads use `multipart/form-data`.
- IDs are UUID strings.
- Timestamps are RFC 3339 strings.
- Durations ending in `_ms` are milliseconds.
- Errors use a stable envelope:

  ```json
  {
    "error": "human-readable message",
    "code": "STABLE_CODE"
  }
  ```

  Some framework-level errors (for example an unknown route) return only
  `{"error":"404 Not Found"}` and no `code`.
- `X-Request-Id` is generated by middleware and included in server logs.

## Probes

The API registers `/healthz`, `/readyz`, and `/api/v1/health`. nginx answers
`GET /healthz` on port 3000 itself with the plain text `ok`; use port 8080 for the
API's JSON probes.

### `GET /healthz`

Liveness only. Returns 200 if the process can respond.

```json
{"status":"ok"}
```

### `GET /readyz`

Readiness. Pings PostgreSQL with a 2-second timeout.

- 200: `{"status":"ready"}`
- 503: `{"status":"unavailable","error":"database unreachable"}`

### `GET /api/v1/health`

Alias of the liveness check; used by the frontend status page.

```json
{"status":"ok"}
```

## Search

### `POST /api/v1/search`

See [Search](search.md) for scoring and semantics.

Request:

```json
{
  "query": "database replication",
  "limit": 10,
  "offset": 0,
  "video_id": "optional-uuid",
  "video_ids": ["optional-uuid", "optional-uuid"]
}
```

| Field | Type | Rules |
|---|---|---|
| `query` | string | Required, non-empty, max 2,000 characters. |
| `limit` | integer | Optional, default 10, range 1–50. |
| `offset` | integer | Optional, default 0, must be ≥ 0. |
| `video_id` | string | Optional existing video UUID. Restricts the search to one video. |
| `video_ids` | string[] | Optional list of video UUIDs (max 500). Restricts the search to those videos; duplicates are ignored. **An empty list is a real empty scope: it returns zero results immediately and is never treated as an unrestricted search.** |

The scope is resolved in this order: `video_id` first, then `video_ids`,
then unrestricted retrieval. The unrestricted fallback exists for backward
compatibility with existing API clients and internal tooling; the browser
frontend always sends an explicit scope. The `video_ids` filter applies to
both the semantic and the lexical candidate retrieval before result fusion.
Unavailable (deleted) video IDs in the list simply contribute no rows
instead of failing the request.

Response 200:

```json
{
  "query": "database replication",
  "limit": 10,
  "offset": 0,
  "duration_ms": 14,
  "results": [
    {
      "chunk_id": "uuid",
      "video_id": "uuid",
      "video_title": "Distributed systems lecture",
      "original_url": "https://www.youtube.com/watch?v=VIDEO_ID",
      "timestamp_url": "https://www.youtube.com/watch?v=VIDEO_ID&t=754",
      "text": "A replica applies the primary's write-ahead log ...",
      "start_ms": 754000,
      "end_ms": 812000,
      "score": 0.03278688524590164,
      "semantic_score": 0.8123,
      "lexical_score": 0.0601,
      "semantic_rank": 2,
      "lexical_rank": 4
    }
  ]
}
```

Errors:

| Status | Code | Cause |
|---|---|---|
| 400 | `INVALID_SEARCH` | Invalid JSON, empty/too-long query, bad limit/offset/UUID. |
| 404 | `VIDEO_NOT_FOUND` | `video_id` does not exist. |
| 500 | `SEARCH_FAILED` | Embedding or database failure/timeout. |

## YouTube ingestion

### `POST /api/v1/videos`

Request:

```json
{
  "url": "https://www.youtube.com/watch?v=VIDEO_ID",
  "language": "en",
  "subtitle_key": "en",
  "subtitle_source": "manual"
}
```

| Field | Type | Notes |
|---|---|---|
| `url` | string | Required HTTPS YouTube video URL. |
| `language` | string | Optional requested language. Empty uses the default selection. |
| `subtitle_key` | string | Optional exact track key from subtitle discovery. |
| `subtitle_source` | string | Optional `manual` or `automatic`; used with `subtitle_key`. |

Response 200: a video object with an optional `transcript` summary.

```json
{
  "id": "uuid",
  "source_type": "youtube",
  "source_ref": "VIDEO_ID",
  "title": "Example video",
  "original_url": "https://www.youtube.com/watch?v=VIDEO_ID",
  "thumbnail_url": "https://i.ytimg.com/...",
  "duration_ms": 634000,
  "channel": "Example channel",
  "language": "en",
  "status": "ready",
  "created_at": "2026-11-03T10:00:00Z",
  "updated_at": "2026-11-03T10:00:02Z",
  "transcript": {
    "id": "uuid",
    "video_id": "uuid",
    "extraction_method": "manual_subtitle",
    "original_format": "vtt",
    "language": "en",
    "cue_count": 42,
    "created_at": "2026-11-03T10:00:02Z"
  }
}
```

Chunking/embedding continues after this response. Poll the processing endpoint
before searching.

Errors are described in [Ingestion](ingestion.md#error-codes). Common cases:
400 invalid/unsupported/playlist URL, 422 video unavailable or no transcript,
429 YouTube rate limit.

### `GET /api/v1/videos/subtitles?url=...`

Discovers compatible subtitle tracks without downloading them. The `url` query
parameter must be URL-encoded.

Response 200:

```json
{
  "video_id": "VIDEO_ID",
  "title": "Example video",
  "metadata": {
    "video_id": "VIDEO_ID",
    "title": "Example video",
    "thumbnail_url": "https://i.ytimg.com/...",
    "duration_ms": 634000,
    "channel": "Example channel"
  },
  "subtitles": [
    {
      "language": "en",
      "name": "English",
      "source": "manual",
      "formats": ["srt", "vtt"],
      "original": false,
      "translated": false
    },
    {
      "language": "en-orig",
      "name": "English (Original)",
      "source": "automatic",
      "formats": ["vtt"],
      "original": true,
      "translated": false
    }
  ],
  "translated_subtitles": [
    {
      "language": "de",
      "name": "German",
      "source": "automatic",
      "formats": ["vtt"],
      "original": false,
      "translated": true
    }
  ]
}
```

## Transcript upload

### `POST /api/v1/transcripts`

`multipart/form-data` fields:

| Field | Required | Notes |
|---|---|---|
| `file` | Yes | `.vtt` or `.srt`, within `TRANSCRIPT_MAX_UPLOAD_MB`. |
| `title` | No | Defaults to filename. |
| `language` | No | Stored as provided. |
| `original_url` | No | Accepted HTTPS YouTube URL; enables timestamp links. |

Response **201** with the same video shape as YouTube ingestion.

Errors: 400 unsupported/invalid file, 413 too large, 500 persistence/artifact
failure.

## Videos

### `GET /api/v1/videos?limit=50&offset=0` (administrative)

Lists the newest videos in the shared database. This endpoint is protected
by the static `ADMIN_API_TOKEN` (see [Configuration](configuration.md)):
present it as `Authorization: Bearer <token>` or in the `X-Admin-Token`
header. Missing or incorrect tokens are rejected with **401**, and the
endpoint rejects every request when no token is configured.

The normal frontend does not use this endpoint; it renders each browser's
locally saved library instead (see "Browser-local video libraries" in the
configuration documentation).

Pagination applies to videos.

- `limit`: default 50, range 1–200.
- `offset`: default 0, must be ≥ 0.

```sh
curl -H "Authorization: Bearer $ADMIN_API_TOKEN" \
  http://localhost:3000/api/v1/videos?limit=50
```

Response 200:

```json
{
  "videos": [
    {
      "id": "uuid",
      "source_type": "upload",
      "source_ref": "sha256...",
      "title": "Example talk",
      "status": "ready",
      "created_at": "2026-11-03T10:00:00Z",
      "updated_at": "2026-11-03T10:00:02Z",
      "transcript": {
        "id": "uuid",
        "video_id": "uuid",
        "extraction_method": "direct_upload",
        "original_format": "vtt",
        "language": "en",
        "cue_count": 5,
        "created_at": "2026-11-03T10:00:02Z"
      }
    }
  ],
  "limit": 50,
  "offset": 0
}
```

### `GET /api/v1/videos/:id`

Returns one video with its transcript summary, or 404 `VIDEO_NOT_FOUND`.

### `DELETE /api/v1/videos/:id` (administrative)

Deletes the video and, by cascade, its transcript, cues, chunks, processing
state, and jobs. Requires `ADMIN_API_TOKEN` (see `GET /api/v1/videos`);
requests without a valid token are rejected with **401**. If artifact
storage is enabled, stored artifacts are also removed.

Note: the UI's "remove from library" action does **not** call this endpoint.
It only removes the video's ID from the current browser's local library and
leaves the database record untouched.

Note: artifact deletion happens after the database delete. If artifact cleanup
fails, the API logs the failure and returns a 500 error, but the database rows
are already gone.

### `GET /api/v1/videos/:id/transcript?limit=50&offset=0`

Returns raw cues ordered by `seq`.

- `limit`: default 50, range 1–200.
- `offset`: default 0.

Response 200:

```json
{
  "video_id": "uuid",
  "cues": [
    {
      "id": "uuid",
      "video_id": "uuid",
      "seq": 1,
      "start_ms": 0,
      "end_ms": 5000,
      "text": "Welcome to the talk."
    }
  ],
  "limit": 50,
  "offset": 0
}
```

Returns 404 if the video does not exist.

## Processing

### `GET /api/v1/videos/:id/processing`

Returns processing progress.

```json
{
  "video_id": "uuid",
  "status": "processing",
  "stage": "embedding",
  "progress_percent": 70,
  "cue_count": 42,
  "embedding_count": 0,
  "chunk_count": 0
}
```

`status` is `pending`, `processing`, `completed`, or `failed`. On failure,
`last_error` is included.

### `POST /api/v1/videos/:id/process`

Runs chunking and embedding synchronously, then returns the resulting state.

- If the video is already complete with the current processing and model
  versions, it returns without duplicating work.
- If processing fails, the state is persisted as `failed` and an error is
  returned.
- The request can take up to `EMBEDDING_TIMEOUT` (default 5 minutes).
- 404 if the video does not exist.

```sh
curl -X POST http://localhost:3000/api/v1/videos/VIDEO_ID/process
```

### `GET /api/v1/videos/:id/chunks?limit=50&offset=0`

Lists derived chunks ordered by `seq`. The response does not expose embedding
vectors.

```json
{
  "chunks": [
    {
      "id": "uuid",
      "video_id": "uuid",
      "start_ms": 0,
      "end_ms": 27000,
      "text": "Welcome ...",
      "created_at": "2026-11-03T10:00:03Z"
    }
  ],
  "limit": 50,
  "offset": 0
}
```

## Error codes

| Code | HTTP status (typical) |
|---|---|
| `INVALID_YOUTUBE_URL`, `UNSUPPORTED_URL`, `PLAYLIST_NOT_SUPPORTED` | 400 |
| `INVALID_SEARCH` | 400 |
| `INVALID_SUBTITLE_FILE`, `INVALID_VTT`, `INVALID_SRT`, `UNSUPPORTED_FILE_TYPE`, `EMPTY_TRANSCRIPT`, `INVALID_TIMESTAMP` | 400 |
| `YTDLP_NOT_INSTALLED`, `YTDLP_TIMEOUT`, `YTDLP_EXTRACTION_FAILED` | 400 |
| `VIDEO_NOT_FOUND` | 404 |
| `FILE_TOO_LARGE` | 413 |
| `VIDEO_UNAVAILABLE`, `VIDEO_INACCESSIBLE`, `NO_TRANSCRIPT`, `LANGUAGE_UNAVAILABLE` | 422 |
| `YTDLP_RATE_LIMITED` | 429 |
| `MINIO_UPLOAD_FAILED`, `DATABASE_PERSISTENCE_FAILED`, `SEARCH_FAILED` | 500 |

The mapping is implemented in `api/internal/server/server.go`. Internal errors
are logged with the request ID; client responses do not expose stack traces or
database details.
